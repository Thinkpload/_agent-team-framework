# Концепция: Виртуальная команда на Claude Code

## Что это и зачем

Стандартная работа с LLM — один разговор, один контекст, всё в кучу. Этот фреймворк разделяет задачи между специализированными агентами с уникальными личностями, экспертизой и зонами ответственности.

**Результат:** вместо «умного ассистента общего профиля» у тебя команда специалистов, каждый из которых думает в своей роли.

---

## Три ключевых паттерна

### 1. Личность > Роль

Агент — это не просто набор инструкций «делай X». Это персонаж с характером, историей, принципами и ограничениями.

**Почему это работает:** LLM с конкретной личностью устойчивее держит контекст и последовательнее ведёт себя. «Финансист-скептик который говорит жёстко» выдаёт другой результат, чем «финансовый аналитик».

**Пример:**
```
❌ Плохо: "Ты финансовый аналитик. Анализируй компании."

✅ Хорошо: "Ты Дмитрий Соловьёв. Прямолинеен, порой жёсток. Если сценарий 
бредовый — скажешь в лицо. Педантичен. Каждая цифра имеет источник. 
'Примерно' не принимаешь."
```

### 2. Двухслойная документация (субагент + досье)

Каждый агент существует в двух файлах:

**`.claude/agents/имя.md`** — технический файл субагента:
- Frontmatter с именем, описанием, инструментами
- Краткий системный промпт: роль, принципы, как работать
- Описание должно точно отвечать на вопрос «когда вызывать»

**`Team/имя.md`** — расширенное досье персоны:
- Полный характер с деталями и нюансами
- История и мотивация
- Зоны ответственности с таблицами артефактов
- Секция «как со мной работать»

Разделение позволяет держать субагентный файл компактным, вынося глубокий контекст в досье, которое агент может читать через инструмент Read.

### 3. HRD как мета-агент (агент, нанимающий агентов)

HRD-агент знает протокол создания новых агентов и при необходимости расширяет команду.

**Протокол найма:**
1. Пользователь говорит продакт-лиду: «Найми юриста»
2. Продакт-лид делегирует Марине: «Марина, найми юриста по M&A»
3. Марина создаёт два файла: `Team/lawyer-name.md` + `.claude/agents/lawyer-name.md`
4. Марина обновляет `Team/roster.md`
5. После этого новый агент реально работает

## Принципы проектирования агентов

### Специализация без пересечений
Каждый агент владеет конкретной зоной. Пересечение зон — источник путаницы. Если задача лежит на стыке — решает тот, кто ближе, или продакт-лид координирует.

### Junior-агент как «дешёвая рабочая сила»
Один агент (обычно на Haiku-модели) берёт рутину: списки, форматирование, черновики, заполнение шаблонов. Это снижает нагрузку на более «умных» и дорогих агентов.

**Правило Junior:** если задача требует «думать» — отказывается и называет, кто подходит.

### Главный контекст = продакт-лид
CLAUDE.md — это «мозг» продакт-лида. Там: миссия проекта, фазы, кто что делает, как начинать сессию. Это единственный файл, который всегда в контексте.

### Агент знает своё досье
Каждый субагент в системном промпте ссылается на свой файл: `Твоё досье: Team/имя.md`. Так он может при необходимости прочитать расширенный контекст о себе.

## Рекомендуемый состав минимальной команды

| Роль | Когда нужна |
|------|-------------|
| **Продакт-лид** (главный CLAUDE.md) | Всегда — координация |
| **HRD-агент** | С первого дня — найм и расширение команды |
| **Junior-ассистент** | С первого дня — рутина |
| **Специалист #1** | Зависит от домена |
| **Специалист #2** | Зависит от домена |

Три агента — минимум для работы. Остальные добавляются по мере появления задач.

---

## Чего НЕ делать

- **Не создавать агентов «на всякий случай»** — агент нужен, когда есть реальный запрос к этой экспертизе
- **Не делать агентов слишком широкими** — «аналитик всего» хуже двух узких специалистов
- **Не копировать личности** — каждый агент уникален, дублирующиеся типажи конкурируют за задачи
- **Не перегружать субагентный файл** — держи его компактным, глубина — в досье
- **Не забывать обновлять roster.md** — реестр должен отражать реальный состав команды

---

## Как концепт масштабируется

```
Фаза 1: 3 агента (HRD + Junior + 1 специалист)
Фаза 2: 5-7 агентов (базовая команда)
Фаза 3: 10+ агентов (полная команда по проекту)
```

Масштабирование через HRD-агента — не через ручное создание файлов.
